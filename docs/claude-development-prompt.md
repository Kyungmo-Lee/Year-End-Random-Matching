# Claude 개발 요청 프롬프트

아래 내용을 Claude Code에 전달하고 프로젝트 폴더에서 실행하세요. 다른 환경에서는 `docs/design.md`도 함께 전달하세요.

---

이 프로젝트의 새해 목표 선물 교환 웹 서비스를 실제로 구현해줘. 계획만 제시하고 끝내지 말고, 설계 문서에 따라 화면·서버·DB·테스트·운영 문서까지 완성해줘.

## 작업 위치와 기준

- 프로젝트: `D:/toy/random-matching/Year-End-Random-Matching`
- 먼저 저장소 지침, `README.md`, `docs/design.md` v1.1을 읽고 현재 파일과 변경 사항을 확인해.
- 기능의 기준은 `docs/design.md`야. 원문 기획의 익명 표시보다 최신 설계의 사용자 직접 설정 닉네임 표시를 우선해.
- 설계 문서의 ‘구현 전’, ‘아직 생성하지 않는다’는 작성 당시 상태야. 이번 요청은 실제 구현을 맡기는 것이므로 로컬 구현·마이그레이션·설정 파일·테스트 작성을 진행해.
- 기존 사용자 변경은 보존해. 실제 요구사항을 바꿀 필요가 있는 경우 이유를 설명하고 확인해. 폴더 구성, 라이브러리 등 일상적인 구현 선택은 판단해서 진행해.

## 기술 구성

React + TypeScript + Vite, Cloudflare Workers + Static Assets, D1, Wrangler를 사용해. 화면과 API는 같은 서비스 주소에서 제공하고 `/api/*`는 Worker가 처리해야 해. 한국어 UI와 모바일 화면을 기본으로 해.

운영 데이터는 D1에 저장하고 개발용 DB와 운영 DB를 분리해. 배포 런타임의 로컬 파일, 브라우저 저장소, Worker 메모리를 운영 DB로 사용하지 마. Cloudflare 공식 문서로 현재 지원 API와 제한을 확인해.

## 구현할 기능

1. 관리자 `/admin`: 비밀번호 인증, 행사명·마감·예산 설정, 참석자 명단 개별/일괄 입력·변경·제외, 활성 명단 기준 인원 자동 계산, 참여 시작 버튼.
2. 참여 등록: 명단에서 본인 이름 선택, 닉네임 직접 입력, 목표 입력, 임시저장, 접속 코드 발급·재접속.
3. 닉네임: 2~20자, 정규화 후 행사 내 중복 차단, 확정 제출 전·마감 전 수정 가능. 명단 이름을 닉네임으로 자동 사용하지 않아야 해.
4. 목표: 1~100자, 확정 제출 전·마감 전 수정 가능. 확정 확인 창에서 닉네임과 목표가 잠긴다고 알려줘. 제출 직후 교환 방법 안내를 표시해.
5. 자동 매칭: 활성 명단 전원이 확정하면 서버에서 Sattolo로 정확히 1:1 배정하고 자기 배정 없이 하나의 사이클을 만들어. 선물 번호는 01~99에서 중복 없이 부여하고 결과를 영구 저장해.
6. 내 페이지: 배정 확인 시 받는 사람의 닉네임·목표·선물 번호와 내 선물 번호를 표시해. 교환 안내를 다시 볼 수 있게 해.
7. 관리자 운영: 명단 이름·닉네임·제출/열람 현황, 등록 초기화, 확정 해제, 코드 재발급, 마감 연장, 마감 후 미확정자 제외와 수동 매칭, 전원 미열람 시 재매칭, 행사 종료.
8. 전체 결과: CLOSED에서 관리자 확인 후 공개하고, 산타 닉네임 → 받는 사람 닉네임만 보여줘. 공개 취소와 관리자 사전 미리보기는 제공하지 않아. 공개 결과에 목표나 명단 이름을 포함하지 마.
9. 종료 후 데이터 삭제: 설계의 7일 기준과 삭제 확인을 적용하고, 닉네임·목표·명단·접속 자격·관련 세션까지 삭제해. DELETED 이후 재등록이나 복구 매칭이 일어나면 안 돼.
10. 매칭 실패 복구: 매분 Cron에서 OPEN·전원 확정 조건을 확인해 안전하게 재시도해. 매칭 실패 때문에 이미 저장된 확정 제출을 취소하지 마.

## 반드시 지킬 구현 조건

- 설계의 상태별 허용 동작과 마감 조건을 UI와 서버 양쪽에서 검증해. 버튼 비활성화만으로 제한하지 마.
- 동시 제출·명단 변경·초기화·열람·재매칭의 경합을 처리해. `revision`, `match_run_id`, 조건부 쓰기, D1 `batch()`를 이용해 상태와 전체 결과를 원자적으로 저장해.
- 조건부 UPDATE의 변경 행 수가 0이면 자동 롤백된다고 가정하지 마. 후속 쓰기에도 작업 소유권 조건을 적용해. D1 호출 사이를 일반적인 연결형 트랜잭션처럼 취급하지 마.
- 목표·번호·상대 닉네임을 반환하기 전에 첫 열람을 기록해. 열람과 재매칭이 경합해도 이미 전달된 결과가 뒤에서 바뀌면 안 돼.
- 참여자에게는 본인 정보와 본인이 배정받은 정보만 제공해. 공개 전 자신에게 선물을 주는 산타, 다른 사람의 목표, 전체 매칭을 반환하지 마. 관리 현황에도 목표와 비공개 배정 결과를 넣지 마.
- 비밀번호 검증 값과 서버 secret은 서버에만 보관해. 접속 코드·세션 토큰은 안전한 난수로 생성하고 DB에는 해시만 저장해. 재발급 시 기존 코드와 세션을 즉시 무효화해.
- 관리자/참여자 세션을 구분하고 쿠키 보안, CSRF·Origin 검증, 로그인 시도 제한, 입력 검증, SQL 바인딩, `no-store`를 적용해. 목표·코드·세션 토큰·전체 매칭을 로그에 기록하지 마.
- 화면 시간은 Asia/Seoul, DB 시간은 UTC를 사용해. 닉네임·목표 길이 계산은 클라이언트와 서버가 일치하도록 정의해.
- 로딩·오류·저장 완료·빈 명단·마감·삭제 상태를 처리하고, 입력 라벨·키보드 조작·확인 모달·복사 버튼 등 기본 접근성을 갖춰줘.

## 개발 및 검증

설계의 구현 순서대로 진행해. 필요한 의존성을 설치하고 D1 SQL 마이그레이션, Wrangler 설정, 로컬 secret 예제, 안전한 비밀번호 검증 값 생성 도구를 작성해. 실제 secret이나 기본 운영 비밀번호를 저장소에 넣지 마.

타입 검사·프로덕션 빌드와 핵심 테스트를 실제로 실행해. 순수 함수 테스트만으로 DB 경합을 검증했다고 하지 말고, Workers/D1 로컬 런타임을 활용해 다음을 확인해:

- 2~99명 매칭의 1:1·자기 배정 없음·단일 사이클·번호 유일성.
- 마지막 두 명 동시 제출, 동일 이름·닉네임 동시 등록, 제출과 명단 변경 경합.
- 매칭 저장 중 오류의 전체 롤백과 복구 재시도.
- 첫 열람과 재매칭 경합, 확정 후 수정 차단, 마감·상태 제한.
- 인증·다른 사람 정보 접근 차단, 관리자 비공개 결과 제한, 공개 결과의 필드 제한.
- 코드 재발급 후 기존 코드·세션 무효화, 삭제 후 조회·재등록·복구 차단.
- 관리자 설정부터 참여·매칭·종료·공개까지 브라우저 흐름과 모바일 표시.

실행 환경 때문에 검증하지 못한 항목은 통과했다고 하지 말고, 제약과 재현 방법을 남겨. 검증 결과에 따라 문제를 고쳐.

## 산출물과 완료 기준

작동하는 앱, API, D1 마이그레이션, 자동화 테스트, 실행 스크립트, 설정 예제, README의 로컬 실행·관리자 초기 설정·운영 배포·삭제 절차를 완성해.

로컬에서는 테스트 명단으로 전체 흐름을 실행할 수 있어야 해. 실제 행사명·명단·마감·예산은 관리자 화면에서 설정하므로 지금 사용자에게 입력을 요구하며 작업을 멈추지 마.

Cloudflare 계정 자격 증명이 없어도 로컬 구현·검증·배포 준비는 끝내고, 실제 계정에서 필요한 D1 생성·마이그레이션·secret 설정·배포 명령을 정리해. 이번 요청은 구현과 배포 준비까지이며, 실제 운영 배포·유료 전환·운영 데이터 삭제는 별도 명시적 승인 후 실행해.

완료 보고에는 구현한 기능, 실행한 검증과 결과, 남은 제약, 로컬 실행 명령, 운영 배포 단계, 참여 링크와 `/admin` 주소를 확인하는 방법을 간결하게 정리해. 실제 배포하지 않았다면 URL이 발급되었다고 쓰지 마.
